# ALIGN 工作闭环

给刚入职的算法工程师用的任务澄清、优先级判断与阶段反馈流程。把整个文件夹上传到自己的 GitHub 仓库即可；`skills/align-workflow/SKILL.md` 是供 agent 读取的技能文件。

## 怎么用

把 `SKILL.md` 所在文件夹放入支持技能的 agent 的技能目录，或在对话里让 agent 读取该文件。之后可以直接说：

> 领导说这周优化推荐页转化，我手头还有 PM 的取数请求和一个线上特征缺失问题。用 ALIGN 帮我排序，并起草需要确认的消息。

agent 会给出优先级依据、任务确认卡、一个低成本验证、下次反馈节点及可直接发送的沟通草稿。所有未知内容会标注待确认，不会被写成已获领导同意。

## 人自己用时

1. 把所有任务记到一个清单，判断业务影响、是否阻塞别人、期限和未知风险。
2. 对预计超过半天的任务，写下目标、交付物、成功标准、期限、决策人，并确认关键空白。
3. 先做最便宜的风险验证，再带初步证据向相关人寻求反馈。
4. 到约 20% 和 60% 进度时，检查方向和交付是否仍正确；这些是练习用的提醒点，不是原书的固定规则。
5. 新证据或优先级变化时，重新决定继续、缩小范围、暂停还是升级讨论。

## 来源与边界

该流程根据上一轮讨论的 Edmond Lau《The Effective Engineer》中 *Prioritize Regularly*、*Invest in Iteration Speed*、*Validate Your Ideas Early and Often*、*Improve Your Project Estimation Skills* 等章节主题改编。ALIGN 名称、五项任务卡、半天触发线、进度百分比及模板是为实际工作设计的操作约定，并非书中原文或经验证的通用阈值。它主要处理工程工作沟通，不替代公司内部的优先级或事故处理制度。
